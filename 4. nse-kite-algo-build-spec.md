Hand this file to an implementing model as the only product spec.

If this file and a model’s taste disagree, this file wins. Do not add indicators, brokers, services, screens, or trades. Do not “improve” the strategy. Build the modules below so two independent implementations pass the same tests.

## 0. Conformance contract

The implementing model must:

1. Create the repository layout in §2 exactly.
2. Keep each module’s public functions, types, reason codes, and formulas identical.
3. Keep network I/O inside `kite_gateway.py` and `api/` only. `indicators`, `bias`, `screener`, `sets`, `risk`, `candles` are pure.
4. Ship the tests in §24. They are the definition of “same output”.
5. Leave `vwap_pullback` implemented and `enabled: false`.
6. Default `LIVE_TRADING` to `"false"` and `risk.trading_mode` to `"paper"`. Paper and live share one state machine.
7. Refuse to start the live order path until the tests pass.

Non-deterministic work is allowed in exactly one place: `review.draft_review()`, and only when a human clicks the button. Everything else is pure or a straight Kite call.

Locked product decisions (do not reopen):

- One account, one EC2 box, Zerodha Kite Connect, NSE + NFO.
- Default phase: `sector_fno_stock` (supports `nifty_only` via rules YAML). Buy ATM options only (`CE` on bullish, `PE` on bearish). No shorts, no spreads, no non-F&O stocks.
- **Bias series:** near-month Nifty futures and Bank Nifty futures; spot `NIFTY 50` for 15m ATR and sector relative baseline; VIX for veto only.
- **Stock signal series:** NSE cash equity (`EQ`) of shortlisted F&O stocks (real volume & VWAP). Spot equity price for ATM strike.
- No new entry before 09:30 IST. No new entry at or after 14:30. Flatten at 15:15. One filled trade per day.
- 1 minute can arm. A closed 5 minute candle confirms. Only the confirm may order.
- Sideways, failed health, missing token, expiry day, no eligible stock, wide spread: no trade.
- Stop = 30% of fill premium. Target = 60% of fill premium (1:2). Also exit on a 1 minute close back through the traded stock's VWAP (or Nifty futures VWAP in `nifty_only`).
- Protective stop is **SL (limit)**, never SL-M.
- Rules (including `risk.trading_mode`) and data files (`sector_fno_map.yaml`, `nse_holidays.txt`, `nifty50.txt`) apply next session, never mid-session.
- AI does not see orders. A template writes the live reason sentence.
- UI polling and config reads (`GET /api/session`, `GET /api/events`, `GET /api/settings`) make **0 Kite API calls**.

## 4. M01 — rules

File: `src/nsebot/rules.py`.

The first boot copies `config/default_rules.yaml` into sqlite table `rules_versions` as version 1 if the table is empty. The engine loads the version with `status = "scheduled"` at the session start latch and stamps `sessions.rules_version`. Edits during the session insert a new version with `status = "scheduled"` and do not touch the running copy.

Validator rejects the document unless every key in the default exists and types match. Unknown keys are rejected. The UI cannot invent keys.

## 7. M04 — Kite gateway

File: `src/nsebot/kite_gateway.py`.

This is the only module that imports `kiteconnect`.

Effective credentials resolve in priority order: `DATA_DIR/credentials.json` (updated via UI Settings, mode `0600`) → `ENV_FILE` / `os.environ` (`KITE_API_KEY`, `KITE_API_SECRET`), never logged. `LIVE_TRADING` (`"true"` or `"false"`, absent means `"false"`) reads **only** from process environment (`ENV_FILE`), never from `credentials.json`.

Token file `DATA_DIR/token.json`:

```json
{"access_token": "...", "user_id": "...", "created_at": "2026-11-13T09:05:00+05:30"}
```

Written via temp file + rename, mode `0600`. Both the engine and local token-status checks treat `created_at` before today’s `06:00 IST` as expired (`no_token`) without calling Kite.

Public API:

```python
class Gateway:
    def __init__(self, api_key: str, access_token: str): ...
    def profile(self) -> dict: ...
    def margins_equity(self) -> dict: ...
    def instruments_csv(self, exchange: str | None = None) -> bytes: ...
    def historical(self, token: int, start: datetime, end: datetime, interval: str) -> list[Bar]: ...
    def quote(self, keys: list[str]) -> dict: ...
    def place(self, **kwargs) -> str: ...
    def modify(self, order_id: str, variety: str = "regular", **kwargs) -> str: ...
    def cancel(self, order_id: str, variety: str = "regular") -> None: ...
    def orders(self) -> list[dict]: ...
    def positions(self) -> dict: ...
    def connect_ticker(self, on_ticks, on_connect, on_close, on_error) -> None: ...
    def subscribe(self, tokens: list[int], mode: str) -> None: ...   # mode "quote" or "full"
    def close(self) -> None: ...
```

Behaviour locks:

- `historical` interval strings are Kite’s: `minute`, `5minute`, `15minute`. Map those to `Bar.timeframe` `1m` / `5m` / `15m`.
- Rate-limit `historical` to at most 2 calls/second.
- `quote` batches at most 200 keys, and at most once per second.
- `place`, `modify`, and `cancel` are refused by this class when `LIVE_TRADING != "true"`. The paper broker never calls them.
- On any `place` / `modify` / `cancel` exception: raise `OrderError` with the broker message unchanged. Do not retry inside the gateway.
- Ticks: convert Kite full or quote packets into `Tick`. `exchange_timestamp` missing → drop the tick and count it. Do not substitute local time.
- Quote mode has no depth: `bid` and `ask` stay `None`. Full mode: best bid = `depth.buy[0].price`, best ask = `depth.sell[0].price`.
- Previous close (`prev_close`) = `ohlc["close"]` from the Kite quote/full packet.

Login (API process only, triggered only when user clicks **Regenerate Kite Token** or submits a `request_token`):

1. Redirect browser to `https://kite.zerodha.com/connect/login?v=3&api_key={key}` (using effective `KITE_API_KEY` and `redirect_url` from `app_settings` if configured).
2. Callback query `request_token`.
3. Checksum = SHA-256 hex of `api_key + request_token + api_secret` (using effective credentials).
4. `POST https://api.kite.trade/session/token` with `api_key`, `request_token`, `checksum`, header `X-Kite-Version: 3`.
5. Store `access_token` and `user_id` atomically in `DATA_DIR/token.json` (`0600`), and enqueue `RELOAD_TOKEN`.

## 8. M05 — instruments & sector map

File: `src/nsebot/instruments.py`.

```python
@dataclass(frozen=True)
class Instrument:
    token: int
    tradingsymbol: str
    exchange: str          # NSE or NFO
    segment: str           # INDICES, NSE, NFO-OPT, NFO-FUT, etc.
    name: str
    expiry: date | None
    strike: Decimal | None
    tick_size: Decimal
    lot_size: int
    instrument_type: str   # EQ, CE, PE, FUT

def load_dump(csv_bytes: bytes) -> list[Instrument]: ...
def load_session_instruments(data_dir: Path, day: date, gw: Gateway) -> list[Instrument]: ...
def require_index(rows, tradingsymbol: str) -> Instrument: ...
def resolve_near_month_fut(rows: list[Instrument], name: str, day: date) -> Instrument: ...
def nifty_options(rows) -> list[Instrument]: ...
def stock_options(rows, underlying: str) -> list[Instrument]: ...
def fno_stock_names(rows) -> set[str]: ...
def resolve_symbols(rows, symbols: list[str]) -> dict[str, Instrument]: ...
def load_sector_map(path: Path, rows: list[Instrument]) -> dict[str, tuple[Instrument, list[Instrument]]]: ...
```

**Dumps:** Must load **both NSE and NFO** rows for today (combined `instruments_csv(None)` or `instruments_csv("NSE")` + `instruments_csv("NFO")` cached as today's CSV). Stale files from previous dates are unusable.

**Filtering:**
- Spot indices: `exchange == "NSE"` and `segment == "INDICES"`: `NIFTY 50`, `INDIA VIX`, plus sectoral indices.
- Cash equities (breadth & stock signals): `exchange == "NSE"` and `instrument_type == "EQ"`.
- Near-month futures (market bias): `exchange == "NFO"` and `instrument_type == "FUT"`, `name in {"NIFTY", "BANKNIFTY"}`, soonest `expiry >= day`.

```python
    tradingsymbol: str

def pct_move(now_px: Decimal, ref_px: Decimal) -> Decimal: ...

    nifty_snap: PriceSnap,
    bias: Bias,

    bias: Bias,
    nifty_snap: PriceSnap,
    sector_snaps: list[PriceSnap],
    stock_snaps: list[PriceSnap],
    sectors_by_symbol: dict[str, tuple[str, ...]],
    rules: Rules,
) -> ScreenerResult: ...
```

Exact formulas (`Decimal`):

1. `pct_move(now_px, ref_px) = (now_px - ref_px) / ref_px * 100` (if `ref_px <= 0`, skip snapshot).
2. `nifty_chg = pct_move(nifty_snap.last, nifty_snap.prev_close)` and `nifty_intra = pct_move(nifty_snap.last, nifty_snap.open_0915)`.
3. For each sector index:
   - `chg_pct = pct_move(last, prev_close)`
   - `intraday_pct = pct_move(last, open_0915)`
   - `rel_strength = (chg_pct - nifty_chg) + (intraday_pct - nifty_intra)`
   - If `bias == BULLISH`: keep `chg_pct > 0 and intraday_pct > 0 and rel_strength > 0`; sort descending by `rel_strength`; keep top `rules.screener.top_sectors` (2).
   - If `bias == BEARISH`: keep `chg_pct < 0 and intraday_pct < 0 and rel_strength < 0`; sort ascending by `rel_strength`; keep top `rules.screener.top_sectors` (2).
   - If `bias == SIDEWAYS`: return empty result.
4. For each F&O stock in `stock_snaps`:
   - `chg_pct = pct_move(last, prev_close)`
   - `intraday_pct = pct_move(last, open_0915)`
   - `rel_strength = (chg_pct - nifty_chg) + (intraday_pct - nifty_intra)`
   - Match against `winning_sector_names`: `matched = [s for s in sectors_by_symbol.get(tradingsymbol, ()) if s in winning_sector_names]`; `in_winning_sector = len(matched) > 0`; assign `sector = matched[0]` else first mapped sector or `""`.
   - `anti_chase_ok = min_stock_move_pct <= abs(chg_pct) <= max_stock_move_pct and volume_today > 0`
   - Filter directionally:
     - `BULLISH`: keep `chg_pct > 0 and intraday_pct > 0`, sort descending by `chg_pct` to take `top_pool` (top 20).
     - `BEARISH`: keep `chg_pct < 0 and intraday_pct < 0`, sort ascending by `chg_pct` to take `top_pool` (top 20).
   - Build `shortlist`:
     - Filter to `anti_chase_ok == True` (and `in_winning_sector == True` when `rules.screener.require_winning_sector` is True).
     - Sort bullish shortlist descending by `rel_strength` (bearish ascending by `rel_strength`). Tie-break alphabetically by `tradingsymbol`.
     - Take up to `rules.screener.shortlist_size` (`5`).

```python
    r: Decimal

def entry_limit(bid: Decimal, ask: Decimal, tick: Decimal) -> Decimal: ...
```

## 16. M12 — execution & M13 — paper broker

- **M12 (`execution.py`):** Calls `gw.place`, `gw.modify`, `gw.cancel`, `gw.orders`.
  - Every order: `variety="regular"`, `exchange="NFO"`, `product="MIS"`, `validity="DAY"`, `tag=D{YYYYMMDD}{n:02d}` (`n = 1 + COUNT(DISTINCT tag) FROM orders WHERE day = today`).
  - Entry: `BUY LIMIT` at `entry_limit` (`ask`).
  - Stop: `SELL SL` (`trigger_price=stop_trigger`, `price=stop_limit_price(stop_trigger, tick)`). Never `SL-M`.
  - Target: `SELL LIMIT` at `target`.
  - Unfilled-stop watchdog (>2s open after `last <= stop_trigger`): prefers `gw.modify` on the SL order; if using cancel/replace, cancels `target` first and waits for terminal `CANCELLED` before replacing.
  - Entry cancel (3s timeout) waits for terminal `CANCELLED` (`filled_qty == 0`) before returning to `WATCHING`. If filled during cancel, go `MANAGING`.
  - Flatten / structure exit: cancel stop & target first, place `SELL LIMIT` at bid, step twice over 5s intervals (`bid`, `bid - 2*tick`).
- **M13 (`paper.py`):**
  - Entry fills at `entry_limit` (**ask**).
  - Paper SL triggers at `last <= stop_trigger`; `px = min(last, bid)` if `bid and bid > 0` else `last`. Fills at `px` **only if `px >= stop_limit_floor`** (never forces `min(px, floor)`). If `px < stop_limit_floor`, stays open until `px >= floor` or watchdog steps down.
  - Target fills at `max(target, bid)` if bid known else `target`. Structure/time exit fills at `bid` if known else `last`.

## 19. M16 — engine

File: `src/nsebot/engine.py`. Single `asyncio` loop ticking every 250 ms; WebSocket ticks pushed via `asyncio.Queue`.

### Subscriptions, Mode Lock, Config/Token Reload & Warmup

- **Startup / 09:00:** `seed_data_files(REPO_DATA_DIR, DATA_DIR)`. Load effective credentials via `load_credentials(DATA_DIR)`. Load scheduled rules and latch them for the session (`sessions.rules_version`, `sessions.mode = active_rules.risk.trading_mode`). Load `DATA_DIR/nse_holidays.txt`, `DATA_DIR/nifty50.txt`, `DATA_DIR/sector_fno_map.yaml`. Load **NSE + NFO** dumps; resolve near-month Nifty & BankNifty FUT, spot `NIFTY 50`, `INDIA VIX`, Nifty 50 breadth symbols, `fno_stock_names`, and `load_sector_map`.
- **09:05 warmup (if token present):**
  - Near-month Nifty FUT & BankNifty FUT `1m` + `5m` (previous trading day).
  - Spot `NIFTY 50` `15m` (~30 calendar days for ATR(14)).
  - Discard bars with `end > now`. Do **not** fetch history for all ~215 F&O stocks at 09:05.
- **09:10 health:**
  - Verify **mode safety lock**: if `active_rules.risk.trading_mode == "live"` and `os.environ.get("LIVE_TRADING", "false").lower() != "true"`, fail closed → `BLOCKED` / `health_fail` (`"live mode requested in rules but LIVE_TRADING env is false"`).
  - Verify token `profile()`, `margins_equity()`, today's instruments, futures/indices resolved, breadth ≥ 48, ≥ 5 sectors resolved (in `sector_fno_stock`), chrony OK, WS connect OK. No live tick required at 09:10.
- **09:15 subscribe (`quote` mode):** Nifty FUT, BankNifty FUT, spot `NIFTY 50`, `INDIA VIX`, Nifty 50 breadth symbols, tracked sector indices, and all F&O cash equities in the sector map (~230 tokens total). Track `open_0915` (first tick/bar open at `>= 09:15`) and `prev_close` (`tick.ohlc.close`, with REST `quote()` fallback at 09:15 for VIX/sectors if missing). Tick freshness (`≤ 2s`) checked from `09:15:05+`.
- **`RELOAD_TOKEN` & `RELOAD_CONFIG` commands (polled every 250ms):**
  - `RELOAD_CONFIG`: reload `DATA_DIR/credentials.json` (updating `KITE_API_KEY`, `KITE_API_SECRET`, `ALERT_WEBHOOK` in memory). If `KITE_API_KEY` changed and token was cleared, move flat non-DONE states to `BLOCKED` (`no_token`) until a new token is saved.
  - `RELOAD_TOKEN`: re-read `DATA_DIR/token.json` and check validity against today's `06:00 IST`.
    - If valid token exists and state is `IDLE` or `BLOCKED` with `block_reason == "no_token"` and `now < no_new_trade_after`: rebuild `Gateway`, reset `warmup`/`health`/`research` latches as needed, transition `BLOCKED -> IDLE`, and let the normal morning sequence catch up cleanly (`warmup -> health -> RESEARCH -> WATCHING`).
    - If valid token is saved while already `MANAGING` / `WATCHING` / `ARMED`: update the `Gateway` access token cleanly in memory without dropping current session state.
    - If token was cleared (`clear`): close `Gateway` ticker cleanly; if flat (`IDLE`/`RESEARCH`/`WATCHING`/`ARMED`), move to `BLOCKED` (`no_token`).

### Screener & Signal Loop (from `09:30` onward)

1. Once Nifty FUT 15m OR completes at `>= 09:30`, compute Index Bias (`M08`). Recompute on every closed `5m` bar while not `MANAGING`/`DONE`/`HALTED`.
2. If `SIDEWAYS` or vetoed → drop any armed stock setups and wait (`WATCHING` / `BLOCKED` on veto).
3. If `BULLISH` or `BEARISH`:
   - In `sector_fno_stock` mode: run `screener.screen_stocks()` at `09:30` and on every closed `5m` bar while in `WATCHING` (do not churn shortlist while `ARMED`, unless an existing arm drops or bias flips).
   - Persist `winning_sectors`, `top_pool` (Top 20), and `shortlist` (top 5) on `sessions` and log `SECTOR_RANKED` when shortlist changes (or `NO_ELIGIBLE_STOCK` if empty).
   - **Just-in-time stock warmup:** For any shortlisted stock not yet warmed up today, call `gw.historical(stock.token, prev_day_start, now, "minute")` and `"5minute"` (discard `end > now`), seed its `1m`/`5m` bars/EMAs/RSIs, and mark warmed.
   - Evaluate active set (`orb_vwap`) on each shortlisted stock's `1m` and `5m` closes (`5m` processed before `1m`).
4. When a shortlisted stock returns `CONFIRM`:
   - Check `user_armed == True` and `now < no_new_trade_after`.
   - Select monthly option via `chain.select_expiry(..., rules)` and `chain.select_atm(..., spot=stock_last)`.
   - REST `quote` on `NFO:{option.tradingsymbol}` for `bid`, `ask`, `bid_qty`, `ask_qty`, `oi`.
   - Check `liquidity_ok` and `risk.build_bracket(entry_limit, tick, lot_size, rules)`.
   - If option fails (`LIQUIDITY_REJECT`, `PREMIUM_TOO_SMALL`, `RISK_CAP`, or `EXPIRY_WEEK_SKIP`): log the reason, clear that stock's arm for this bar, and return/stay `WATCHING` (other shortlisted stocks remain active).
   - If option passes: lock `active_underlying = stock`, clear other arms, transition `ARMED -> ENTRY_WORKING`, place LIMIT BUY at `ask` via `execution` (if `active_mode == "live"` and `LIVE_TRADING == "true"`) or `paper` (if `active_mode == "paper"`).
5. Once `MANAGING`, subscribe the bought option token in `full` mode. Monitor stop (`SL`), target (`LIMIT`), **structure exit (`1m` close of `active_underlying` stock crossing that stock's VWAP)**, blind-feed check (socket age > 15s + REST `quote` fallback), and `15:15` flatten.

### Legal State Transitions

| From | To | When |
|---|---|---|
| IDLE | BLOCKED | weekend, holiday, expiry day, no token, health fail, mode lock mismatch, breadth incomplete, warmup fail |
| BLOCKED | IDLE | `RELOAD_TOKEN` with valid token when `block_reason == "no_token"` and `now < no_new_trade_after` |
| IDLE | RESEARCH | 09:15 and token present and health ok and calendar ok and not expiry |
| RESEARCH | WATCHING | opening range complete and first bias computed, and time `>= 09:30` |
| RESEARCH | BLOCKED | veto `VIX_UNSTABLE` or `DEAD_RANGE` or `BREADTH_INCOMPLETE` |
| RESEARCH | DONE | clock `>= no_new_trade_after` (`window_closed`) |
| WATCHING | ARMED | active set returns ARM |
| WATCHING | DONE | clock `>= no_new_trade_after` |
| ARMED | WATCHING | set returns DROP and time `< no_new_trade_after` |
| ARMED | DONE | still armed at `no_new_trade_after` |
| ARMED | ENTRY_WORKING | CONFIRM and chain + risk pass |
| ARMED | WATCHING | CONFIRM but chain or risk rejects (`liquidity_reject` / `premium_too_small` / `risk_cap` / `expiry_week_skip`) |
| ENTRY_WORKING | MANAGING | entry filled |
| ENTRY_WORKING | WATCHING | not filled in 3s, cancel confirmed (`filled_qty==0`), `< no_new_trade_after` |
| ENTRY_WORKING | DONE | not filled and `>= no_new_trade_after` |
| MANAGING | DONE | stop, target, structure exit, or time flatten, and broker flat |
| any | HALTED | kill switch, blind feed, double mismatch, unretried order reject |
| HALTED | DONE | only after broker is flat |

### Restart Recovery

- `DONE` / `HALTED` stay terminal. `MANAGING` / `ENTRY_WORKING` reconcile immediately against Kite `positions()`/`orders()` before signal logic and resume or flatten. `WATCHING` / `ARMED` rebuild candles via fresh warmup, clear arms, and resume `WATCHING`.
